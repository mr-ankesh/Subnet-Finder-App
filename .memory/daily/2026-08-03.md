## Bugs Fixed (caught during this session's own implementation, before commit)

- `condition_eval.py`: 3 bugs in the condition-string rewriter (string-literal
  re-quoting, lowercase boolean words, dotted-attribute-access quoting) —
  all caught by testing against the KB's actual condition strings, not
  synthetic ones.
- `prefill.py`: the `service_class` field was silently never flagged as
  unfillable (a dead code path that patched a KB list entry that doesn't
  exist) — fixed to always append an explicit checklist entry.
- `templates/advisor.html`: "Change answer" would silently skip past the
  question being changed instead of re-asking it (the server has no
  "re-ask" concept — an answered question is just skipped by
  `next_question()`) — fixed by caching the full question object
  client-side instead of re-querying the server.
- `config.py`/`templates/requester.html`: `Premium_ZRS` was missing from
  `STORAGE_SKUS` and the form's SKU dropdown entirely — `storage_premium_temporary`'s
  recommended SKU had no way to actually be selected/validated. Fixed by
  widening the allowed set (not weakening `_validate_storage_request`).

- User asked to make the Advisor recommend **Azure CNI Overlay** for all
  AKS patterns. Checked `config.py`/`templates/requester.html` first and
  found the real app **already defaults to Overlay**
  (`AKS_NETWORK_PLUGIN_MODE=overlay`, `AKS_POD_CIDR=10.244.0.0/16`) — the
  advisor's KB was the one out of date, still describing classic
  VNET-integrated CNI and warning about per-pod VNET IP exhaustion (a
  problem Overlay already solves). Updated `aks_private_standard.yaml`
  (design/summary/prerequisites), `aks_decision_matrix.yaml`'s `cni_sizing`
  warning, and `aks_request_mapping.yaml`'s `locked_fields`
  (`network_plugin_mode: overlay`) — sourced against the app's own live
  Settings default rather than the pattern's two external cited documents,
  since neither speaks to Overlay; noted honestly in the pattern's own
  `source` list instead of fabricating a citation. `aks_gpu_nodepool.yaml`
  picked up the fix automatically via `design.inherits`.
- **Real bug found and fixed while verifying this live**: `advisor/prompts.py`'s
  LLM client had no read timeout on the Anthropic/Azure-OpenAI paths, and
  only a 60s timeout *with default retries* on the OpenAI-compatible path
  (the one actually configured here, `AGENT_PROVIDER=byom` pointing at an
  internal-only endpoint unreachable from this sandbox) — retries meant a
  real request could take 60-180s to fall back instead of failing fast,
  undermining "AI enhances, never gates." All three paths now use a 15s
  timeout with `max_retries=0`.
- Verified live against the running app (confirmed `design.network_plugin
  == "Azure CNI Overlay"` and the corrected warning render correctly in a
  real recommendation) and via the assert suite (175 checks, +3 for this
  change). Fallback now resolves in ~16s instead of 60-90s+.
