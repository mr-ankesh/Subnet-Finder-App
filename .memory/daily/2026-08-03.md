# 2026-08-03

## Work Completed

- Built the **AI Architecture Advisor V1 (Storage only)** end-to-end, per a
  fully-specified user request: a checked-in knowledge base at `advisor_kb/`
  (5 catalog patterns, a question bank, a deterministic decision matrix, a
  request-field mapping, a recommendation template with 3 system prompts,
  and Mermaid diagram templates), all provenance-tracked to two Microsoft/
  Kyndryl design documents.
- Went through Plan Mode first per the user's explicit "plan, wait for OK,
  then implement in stages" instruction — read the entire KB before writing
  any code, forked a research pass over existing conventions
  (`agent_requester.py`'s LLM-client pattern, `chats.py`'s persistence
  shape, the storage validation chokepoint, nav/vendor precedent), then
  wrote and got approval on a staged plan.
- Implemented in 6 stages, each independently verified before moving on:
  1. `advisor/catalog_loader.py` (loads + validates the KB, fails loudly on
     malformed YAML — verified with deliberately broken test fixtures) +
     `advisor/session_store.py` (new `advisor_sessions` table, own
     `ensure_table()`, added to `scripts/sqlite_to_postgres.py`).
  2. `advisor/condition_eval.py` (a small restricted-`eval()` evaluator for
     the KB's `when`/`skip_if` condition language — found and fixed 3 real
     bugs against the KB's *actual* condition strings: re-quoting
     identifiers already inside string literals, lowercase `true`/`false`
     not converting to Python booleans, and dotted attribute access
     (`derived.lifecycle_to_archive`) being incorrectly quoted token-by-token),
     `advisor/question_engine.py`, `advisor/rules_engine.py`,
     `advisor/pattern_matcher.py` — all pure logic, verified via a new
     assert-based `scripts/test_advisor_validation.py` against the real KB
     content (not mocks), covering 8 of the user's 13 verification items
     directly.
  3. `advisor/prefill.py` + `advisor/diagram_builder.py` — found 4 more real
     mismatches between the KB's semantic vocabulary and this app's actual
     form markup (read `templates/requester.html` directly rather than
     assuming): `identity_type`/`encryption_type` values needed translating
     to the form's actual `<option>` values; `storage_premium_temporary`'s
     `Premium_ZRS` SKU had no matching form option at all (fixed — added to
     `config.py`'s `STORAGE_SKUS` and the form dropdown, a genuine
     pre-existing gap this surfaced); the KB's `ServiceClass` tag mapping
     doesn't match the form's actual options at all (left for the user to
     pick, per the KB's own hedge that this mapping is "inferred, not
     quoted").
  4. `advisor/prompts.py` (single-turn LLM call, no tool loop — unlike
     `agent_requester.py`) + `advisor/recommendation.py` (assembles the
     fixed-section-order recommendation; only "Why this pattern" is
     genuinely LLM prose, with a deterministic fallback) + 3 new `app.py`
     routes + the `requester_page()` extension for the prefill handoff.
     Verified via Flask's test client end-to-end, including a real
     unplanned LLM failure (expired provider license, 403) that correctly
     fell back to the deterministic recommendation rather than erroring.
  5. `templates/advisor.html` (chat UI, answer review/correct step,
     recommendation rendering, diagram request) + `templates/requester.html`
     prefill JS (generic `[data-detail]` population, no hand-written
     per-field mapping) + `templates/base.html` nav (both the admin
     Operations dropdown and the non-admin requester nav branch) + vendored
     Mermaid. Found and fixed a real client-side logic bug during review:
     the "Change answer" button called the server with no question id,
     which just returns whatever's next rather than re-asking the changed
     question — fixed by caching the full question object client-side.
  6. This update.
- Vendored Mermaid as the single-file UMD build (`mermaid.min.js`, 3.3 MB),
  not the ESM build the KB's own diagram README shows — the ESM entry file
  turned out to be a 76-byte re-export pointing at 121 separate hash-named
  chunk files, too fragile to vendor reliably for one feature.

## Bugs Fixed (caught during this session's own implementation, before commit)

- `condition_eval.py`: 3 bugs in the condition-string rewriter (string-literal
  re-quoting, lowercase boolean words, dotted-attribute-access quoting) —
  all caught by testing against the KB's actual condition strings, not
  synthetic ones.
- `prefill.py`: the `service_class` field was silently never flagged as
  unfillable (a dead code path that patched a KB list entry that doesn't
  exist) — fixed to always append an explicit checklist entry.
- `templates/advisor.html`: "Change answer" would silently skip past the
  question being changed instead of re-asking it (the server has no
  "re-ask" concept — an answered question is just skipped by
  `next_question()`) — fixed by caching the full question object
  client-side instead of re-querying the server.
- `config.py`/`templates/requester.html`: `Premium_ZRS` was missing from
  `STORAGE_SKUS` and the form's SKU dropdown entirely — `storage_premium_temporary`'s
  recommended SKU had no way to actually be selected/validated. Fixed by
  widening the allowed set (not weakening `_validate_storage_request`).
