# 2026-08-02

## Work Completed

- Designed and implemented a new **Resource Relationship Graph** module
  end-to-end (V1, read-only — no Azure mutations), per the user's full spec:
  a visual node/edge map of Azure resource dependencies (Network, Compute,
  Platform/AKS, Storage, Security) for troubleshooting, governance and
  impact analysis.
- Went through the full research → plan-mode → phased-implementation process
  (same as the Storage feature): researched `optimize.py`'s standalone-
  read-only-module pattern as the architectural precedent (not the
  `RequestType` lifecycle AKS/VM/Storage use), resolved two open questions
  with the user via `AskUserQuestion` (isolated 4th Reader-only SP; SDK-
  rooted traversal), wrote a plan (`resourcegraph.py`, `config.py` settings,
  3 `app.py` routes, Cytoscape.js frontend), got it approved, implemented in
  3 phases (backend → frontend → docs/memory).
- **Revised the discovery method during planning** (flagged explicitly, not
  silently): pure forward SDK traversal can't answer "start at a Route
  Table" or "start at a Private DNS Zone" — those types don't carry
  properties pointing back at what references them. Added a one-shot Azure
  Resource Graph (ARG) reverse index per request so the BFS walks both
  directions; SDK calls still do all node enrichment and the sub-resource
  fetches ARG can't provide (blob containers, PE DNS zone groups, AKS node
  RG's LB/Public IP).
- Wrote `scripts/test_resourcegraph_validation.py` (32 assert-based checks,
  no Azure needed) covering the pure logic — path extraction, category
  classification, reference-map edge extraction, subnet synthesis, CMK URI
  resolution, and `build_graph()`'s BFS/truncation/seed-resolution behavior
  against a mocked `_arg()`.
- **Caught and fixed 3 real bugs before/during real-Azure testing**:
  1. (offline test caught) `forward` edge-map keys used original-case
     resource IDs while `id_map`/`included`/`reverse` used lowercase,
     silently breaking the primary forward-direction lookup. Fixed with one
     `_add_edge()` helper all edge insertion now goes through.
  2. (offline test caught) "Resource Type selected, no Resource Name" — a
     combination the form explicitly allows — silently fell back to
     whole-subscription mode and dropped the type filter. Fixed with a
     dedicated type-only seed-resolution branch.
  3. (real-Azure test caught, offline mocks missed it) ARM sub-resources
     embedded in an array (a NIC's `ipConfigurations[]`) wrap their own
     fields in a *nested* `properties`, not flat on the array item — real
     data has `ipConfigurations[].properties.subnet.id`, not
     `ipConfigurations[].subnet.id`. Fixed generically in `_walk()` (falls
     through into an item's nested `properties` when a key isn't found
     directly) rather than patching every affected reference path by hand.
- Ran real-Azure verification (subscription `845e564b-31a3-44b0-b030-226798b31574`,
  "Sandbox Connectivity", using the same credential values as the main
  automation SP for testing purposes — a real dedicated Reader-only SP is a
  follow-up item):
  - Whole-subscription mode: 42 real nodes, 32 real edges, no crashes.
  - VNet/Subnet/NSG/RouteTable chains render correctly.
  - Private DNS Zone rooted **directly at the zone** (no VNet given) shows
    its `virtualNetworkLinks` → linked VNet → subnets — proof the ARG
    reverse-index design actually closes the gap it was built for.
  - Deployed one temporary real VM via the existing VM_CREATE feature
    (Standard_B1s, reusing `rg-claude-e2e-qa-test` from the 2026-08-01 QA
    pass) specifically to verify the VM→NIC→Disk→Subnet→VNet/RouteTable
    chain from the spec's own example — rendered correctly. Reverted via the
    Change Ledger afterward; independently confirmed cleanup via `az
    resource list` (empty) and a Resource Graph query for the deleted VM
