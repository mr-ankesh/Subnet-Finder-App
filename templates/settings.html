Prerequisites — Azure Entra ID & Keycloak
Approvals are routed to each requester's line manager. That relationship must flow from Azure Entra ID into Keycloak and out as a token claim. Do this once:
On Azure Entra ID
  1. Ensure every requester has their Manager set (User → Profile → Manager). Entra exposes this as the manager relationship.
  2. The Keycloak user federation / directory sync must import users with the manager attribute (map the manager's email/UPN, not the raw object DN).
On Keycloak
  1. Realm → your client (or a client scope) → Mappers → Add mapper → By configuration → User Attribute.
  2. User Attribute = the synced manager attribute; Token Claim Name = manager (match the “Manager token claim” field above).
  3. Enable Add to ID token, Add to access token and Add to userinfo. Claim type: String.
  4. Also confirm Auth provider = keycloak and the SSO connection is filled in under Authentication.
  5. Sign out and sign in once — the platform records that the claim is present, which satisfies the dependency check.
Full guide: docs/KEYCLOAK.md → “Line-manager approval”.
Per-type approval policy
Choose, per request type, whether approval is Required, left to admin discretion, or not required — and when it's enforced. Most network changes need none; cost/compute-heavy types (e.g. AKS) are the usual candidates. Remember to Save Approvals after editing.
